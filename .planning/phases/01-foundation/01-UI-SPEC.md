# Phase 1 — UI Design Contract

> Visual and interaction contract for **Foundation scaffolding only**.
> Scope: SPA shell, sidebar, wordmark, route placeholders, API health pill, design tokens.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Out of scope for this UI-SPEC** (will land in Phase 2+):
- Product/Movement forms, tables, modals
- 4-state list patterns (loading / empty / error / data)
- Toast component
- Empty/error states for data screens
- Soft-delete and outbound confirmation modals

---

## Design System

| Property | Value |

## Spacing Scale

Tailwind default 4px-base scale (multiples of 4). Phase 1 shell uses the following slots:

| Token | Value | Tailwind class | Usage in Phase 1 shell |
|-------|-------|----------------|------------------------|
| xs | 4px | `gap-1`, `p-1` | Inline icon-to-text gap inside health pill |
| sm | 8px | `gap-2`, `px-2`, `py-2` | Sidebar item vertical padding (`py-2.5` ≈ 10px is the documented exception below) |
| md | 16px | `gap-4`, `p-4`, `px-4` | Sidebar horizontal padding, nav-item horizontal padding |
| lg | 24px | `gap-6`, `p-6` | Main content padding, sidebar section vertical rhythm |
| xl | 32px | `gap-8`, `p-8` | Reserved — not used in Phase 1 shell |
| 2xl | 48px | — | Reserved — not used in Phase 1 shell |
| 3xl | 64px | — | Reserved — not used in Phase 1 shell |

**Layout grid (Phase 1 shell):**
- Sidebar width: `w-60` (240px) fixed left
- Main content: `flex-1` with `p-6` (24px) padding
- Sidebar internal padding: `p-4` (16px) outer, `gap-1` (4px) between nav items

**Documented exception:** Sidebar nav items use `py-2.5` (10px) — codified in `frontend/CLAUDE.md` §"Catálogo de classes recorrentes" as the established Sidebar item pattern. Carried verbatim to preserve consistency with the rest of the brand catalog.

## Typography

Hierarchy (per `frontend/CLAUDE.md` §"Tipografia"): **2 heading sizes + 1 body + 1 caption. Nothing more.**

| Role | Size | Tailwind | Weight | Line Height | Usage in Phase 1 shell |
|------|------|----------|--------|-------------|------------------------|
| Body | 14px | `text-sm` | 500 (`font-medium`) | 1.5 (`leading-normal`) | Sidebar nav item labels |
| Caption | 12px | `text-xs` | 500 (`font-medium`) | 1.5 | Health-status pill text, route placeholder helper text |
| Heading H2 | 18px | `text-lg` | 600 (`font-semibold`) | 1.4 (`leading-snug`) | Wordmark in sidebar, route placeholder titles ("Produtos", "Movimentação de Estoque") |
| Heading H1 | 24px | `text-2xl` | 600 (`font-semibold`) | 1.2 (`leading-tight`) | Reserved — not used in shell, lands in Phase 2 page titles |

**Font weights declared:** `font-medium` (500) + `font-semibold` (600). Inter is loaded with 400/500/600/700 so 400 (`font-normal`) and 700 (`font-bold`) are available but **not used in Phase 1 shell**.

**Wordmark spec** (per `frontend/CLAUDE.md` and FRONT-11):
```html
<h1 class="text-lg font-semibold text-ink">
  Stock<span class="text-brand-500">Easy</span>
</h1>
```
- "Stock" in `text-ink` (#212121)
- "Easy" in `text-brand-500` (#1863DC)
- Inter, 18px, semibold
- Lives at the top of the sidebar, never duplicated in the main content area

## Color

60 / 30 / 10 split applied to the shell:

| Role | Token | Value | Usage in Phase 1 shell |
|------|-------|-------|------------------------|
| Dominant (60%) | `bg-white` | `#FFFFFF` | App background, sidebar background, main content background |
| Secondary (30%) | `text-ink`, `text-muted`, `border-line`, `bg-surface` | `#212121` / `#7B7B7B` / `#EBEBEB` / `#F4F4F4` | Body text, secondary text, sidebar/main divider, hover surfaces |
| Accent (10%) | `brand-500`, `brand-50`, `brand-700` | `#1863DC` / `#EFF4FC` / `#003F7D` | Reserved list below |
| Destructive | `danger` | `#CF2E2E` | API offline indicator text & icon only (no destructive actions in Phase 1) |
| Success | `success` | `#009C34` | API connected indicator text & icon only |

**Accent reserved for (Phase 1 shell — exhaustive list):**
1. Wordmark accent letter: "Easy" in `text-brand-500`
2. Active sidebar nav item background: `bg-brand-50`
3. Active sidebar nav item text & icon: `text-brand-700`
4. Focus ring on focusable elements (nav links): `focus:ring-2 focus:ring-brand-500`

**Inactive sidebar nav items:** `text-muted` with hover `hover:bg-surface hover:text-ink` — accent never appears on inactive items.

**Semantic color rule:** `success` and `danger` in Phase 1 appear **only inside the health-status pill** (see Health Indicator section). They are NOT used elsewhere in the shell.

**Full `brand-50..900` palette must be wired in `tailwind.config.js`** (FRONT-02) even though only `brand-50`, `brand-500`, `brand-700` are consumed by the Phase 1 shell — Phase 2+ will use the rest.

## Interaction Contracts

### Sidebar Nav Item

**Three visual states** (per `frontend/CLAUDE.md` §"Routing" + §"Catálogo de classes recorrentes"):

| State | Trigger | Classes |
|-------|---------|---------|
| Active | `$route.path.startsWith(item.basePath)` | `bg-brand-50 text-brand-700 flex items-center gap-3 px-4 py-2.5 rounded-md text-sm font-medium` |
| Inactive | not active | `text-muted hover:bg-surface hover:text-ink flex items-center gap-3 px-4 py-2.5 rounded-md text-sm font-medium transition-colors` |
| Focused (keyboard) | `:focus-visible` on `<RouterLink>` | Same as state + `focus:outline-none focus:ring-2 focus:ring-brand-500 focus:ring-offset-1` |

**Icon contract:**
- All icons from `lucide-vue-next`
- Size: `w-5 h-5` (20px)
- `aria-hidden="true"` (label provides accessible name)
- Stroke inherits `currentColor` so it matches the text color of the parent state

**Active match strategy:** Use `startsWith(item.basePath)` not exact match — keeps "/products/123" highlighting "Produtos" later in Phase 2.

### Route Placeholder Pattern

Both `/products` and `/stock-movements` pages in Phase 1 render the same minimal placeholder:

```vue
<template>
  <section class="max-w-2xl">
    <h2 class="text-lg font-semibold text-ink mb-2">{{ title }}</h2>
    <p class="text-sm text-muted">{{ description }}</p>
  </section>
</template>
```

- Uses page-level title (not h1) because the wordmark is the single H1 on the page (a11y: one H1 per page)
- No skeleton, no spinner, no empty state — just a labelled "Em breve" message
- `max-w-2xl` matches the form max-width pattern from `frontend/CLAUDE.md` so Phase 2 forms slot in without layout shift

### Health-Status Pill

Discreet indicator pinned to bottom of sidebar (`mt-auto` on its container). Calls `GET /api/health` from `App.vue` `onMounted` hook.

**Three states** (state transitions are LOCKED — better-UX behavior: a degraded API or DB-down outage should surface as "API offline" so the user sees dependency outages, not just transport-level failures):

| State | Icon (lucide) | Container classes | Icon classes | Text |
|-------|---------------|-------------------|--------------|------|
| Checking (initial, before response) | `Loader2` | `inline-flex items-center gap-2 px-3 py-1.5 rounded-md bg-surface` | `w-4 h-4 text-muted animate-spin` | `Verificando API…` in `text-xs text-muted` |
| Connected (HTTP 2xx AND response body has `status: 'ok'` AND `db: 'up'`) | `Check` | `inline-flex items-center gap-2 px-3 py-1.5 rounded-md bg-success/10` | `w-4 h-4 text-success` | `API conectada` in `text-xs font-medium text-success` |
| Offline (any other outcome: non-2xx, network error, timeout > 5s, OR 2xx with `status != 'ok'` OR `db != 'up'`) | `XCircle` | `inline-flex items-center gap-2 px-3 py-1.5 rounded-md bg-danger/10` | `w-4 h-4 text-danger` | `API offline` in `text-xs font-medium text-danger` |

**Behavior rules:**
- Single fetch on mount — no polling in Phase 1
- 5-second timeout — after that, transition to "offline"
- Cor + ícone + texto (3 signals) — color is never the sole indicator (UX-13 a11y rule respected proactively even though UX-* requirements land in Phase 2)
- Pill is **non-interactive** in Phase 1 (no retry click) — Phase 2 onward may add a retry affordance

## Accessibility Floor (Phase 1 shell)

Even though full UX-12/UX-13 a11y requirements land in Phase 2, the shell must already comply:

- `<aside>` element wraps the sidebar (semantic landmark)
- `<main>` element wraps `<router-view/>` (semantic landmark)
- Wordmark is the single H1 on the page (`<h1>Stock<span>Easy</span></h1>`)
- Page-level titles inside route components are H2
- Nav uses `<nav aria-label="Navegação principal">` wrapping the `<RouterLink>` list
- Icons inside nav items have `aria-hidden="true"` (text label provides accessible name)
- Focus ring `focus:ring-2 focus:ring-brand-500` on every `<RouterLink>` — never `outline: none` without substitute
- `document.title` updates from `route.meta.title` so screen readers announce page changes
- Color contrast: `text-ink` (#212121) on `bg-white` = 16.1:1 (AAA); `text-muted` (#7B7B7B) on `bg-white` = 4.7:1 (AA); `text-brand-700` (#003F7D) on `bg-brand-50` (#EFF4FC) = 11.8:1 (AAA). All pass.

## Don'ts (Phase 1 shell)

- ❌ Component library (PrimeVue, Vuetify, Element Plus, shadcn-vue) — Tailwind-only per D14
- ❌ Top header bar / breadcrumbs — sidebar is the only chrome in Phase 1
- ❌ Toasts, modals, dropdowns — those arrive with Phase 2
- ❌ Loading skeletons for `/products` or `/stock-movements` placeholders — there's no data to load
- ❌ Dark mode toggle (PROJECT.md: out of scope)
- ❌ Responsive sidebar collapse — desktop-first MVP
- ❌ Icons other than `Package`, `ArrowLeftRight`, `Check`, `XCircle`, `Loader2` — anything else lands in later UI-SPECs
- ❌ Health-pill polling, retry button, expanded panel — single onMount fetch only
- ❌ Any `bg-brand-500` / brand color usage outside the reserved-for list above
- ❌ Adding font weights beyond 500 and 600 in shell components
