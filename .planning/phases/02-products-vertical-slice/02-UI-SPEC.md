# Phase 2 — UI Design Contract

> Visual and interaction contract for **Products CRUD + UX foundation primitives**.
> Scope: `ProductsPage` (4-state list), Create drawer, Detail drawer, Soft-delete confirmation modal, toast system, and the base primitive set Phase 3 will reuse verbatim.
> Generated by gsd-ui-researcher (auto mode), verified by gsd-ui-checker.

**Extends Phase 1 UI-SPEC** — palette, typography, spacing, sidebar, wordmark, and accessibility floor are **already locked** there and inherited as-is. This document only declares the **net-new** tokens, patterns, and copy that Phase 2 introduces. Wherever a value is unchanged from Phase 1, the cell reads `inherited from Phase 1 §<section>`.

**Out of scope for this UI-SPEC** (Phase 3 territory — explicitly NOT specified here):
- `InboundForm`, `OutboundForm`, `ConfirmOutboundModal`, `MovementHistory`
- Saldo display "Disponível: N unidades" (UX-08)
- Product picker usage of `BaseSearchableSelect` (component authored here, applied in Phase 3)
- Idempotency-Key generation surface
- Movement-specific error codes (`INSUFFICIENT_BALANCE`, `MISSING_IDEMPOTENCY_KEY`, etc.)
- Product **edit/update** flow (out of scope per CONTEXT.md `<deferred>`)

## Spacing Scale

Inherited 4px-base scale from Phase 1 §Spacing. Phase 2 introduces these **new slot usages**:

| Token | Value | Tailwind | New usage in Phase 2 |
|-------|-------|----------|----------------------|
| xs | 4px | `gap-1`, `p-1` | Icon-to-text gap inside `BaseBadge` and toast icons |
| sm | 8px | `gap-2`, `px-2`, `py-2` | Table cell vertical padding (data density), badge inner padding `px-2 py-0.5`, toast inner padding |
| md | 16px | `gap-4`, `p-4` | Form field vertical rhythm (between label-group and next field), modal content padding outer ring |
| lg | 24px | `gap-6`, `p-6` | Card/section padding, drawer/modal content padding, table outer padding, page section gap |
| xl | 32px | `gap-8`, `p-8` | Empty state vertical padding (illustration + heading + CTA stack) |
| 2xl | 48px | — | Reserved — not used in Phase 2 |
| 3xl | 64px | — | Reserved — not used in Phase 2 |

**Documented exceptions** (these are NOT free invention — they extend the catalog from `frontend/CLAUDE.md`):
- Sidebar nav items: `py-2.5` (10px) — **inherited** from Phase 1 §Sidebar
- Table row min-height: **44px** — meets WCAG 2.1 minimum touch target (delete affordance on row hover) — implemented as `py-3` (12px) on `<td>` plus inherent line-height. Documented because 12px is a 4-multiple but not in the named scale slots.
- Badge vertical padding: `py-0.5` (2px) — **inherited** from `frontend/CLAUDE.md` §"Catálogo de classes recorrentes" (Tag Entrada / Tag Saída) — the badge is intentionally tight for inline use; this is the only sub-4px value tolerated and it is locked by the existing catalog.
- Input padding: `px-3 py-2` (12px / 8px) — **inherited** from `frontend/CLAUDE.md` §"Catálogo" (Input row). 12px is a 4-multiple. Lock.

## Color

60 / 30 / 10 split inherited from Phase 1. Phase 2 introduces **two new application contexts**: semantic state colors leave the health pill and now apply to forms, toasts, badges, and confirmations.

| Role | Token | Hex | New usage in Phase 2 |
|------|-------|-----|----------------------|
| Dominant (60%) | `bg-white` | `#FFFFFF` | Page background, drawer background, modal background, toast background, table row background, input background |
| Secondary (30%) | `text-ink`, `text-muted`, `border-line`, `bg-surface` | `#212121` / `#7B7B7B` / `#EBEBEB` / `#F4F4F4` | Body text, secondary text (placeholders, deleted-row labels), table dividers, input border, hover row `bg-surface`, modal/drawer overlay base, skeleton `bg-line animate-pulse` |
| Accent (10%) | `brand-500`, `brand-50`, `brand-600`, `brand-700` | `#1863DC` / `#EFF4FC` / `#0056A7` / `#003F7D` | See exhaustive list below |
| Destructive | `danger`, `red-700` | `#CF2E2E` / `#B91C1C` | Soft-delete button, `Excluir` confirm button, error toast bar, input-error border + helper, `deletedAt` value in detail drawer |
| Success | `success` | `#009C34` | Success toast bar, success icon |
| Warning | `warning` | `#FCB900` | `Excluído` badge background (`bg-warning/10`) + text (`text-warning`) — surfaces deleted rows when "Mostrar excluídos" toggle is on |
| Info (read-only) | `brand-500` | `#1863DC` | Info toast bar (rare in P2; reserved for future use) |

**Accent reserved for** (Phase 2 — exhaustive, append-only to Phase 1 list):
1. Wordmark "Easy" — inherited
2. Active sidebar nav item — inherited
3. Focus ring `focus:ring-2 focus:ring-brand-500` on **every** focusable element (input, button, toggle, dropdown trigger, table row when keyboard-focused) — extends Phase 1 rule
4. **Primary buttons** — `bg-brand-500 hover:bg-brand-600 disabled:bg-brand-200 text-white` (Cadastrar in Create drawer, "Cadastrar primeiro produto" in empty state, "Tentar novamente" in error state)
5. **Primary text links** — `text-brand-600 hover:text-brand-700 underline-offset-2 hover:underline` (none in Phase 2 outside the `_links` actions if surfaced — currently not surfaced visually)
6. **Table header background + text** — `bg-brand-50 text-brand-700` (per `frontend/CLAUDE.md` catalog)
7. **Pagination active page button** — `bg-brand-50 text-brand-700` (matches table header)
8. **Toggle switch (on state)** — `bg-brand-500` thumb track when "Mostrar excluídos" is ON

**Accent forbidden on:** secondary buttons (Cancelar uses `border border-line text-ink hover:bg-surface`), table body cell text (uses `text-ink`/`text-muted`), badge backgrounds other than the brand ones already listed, drawer/modal backdrop (uses `bg-ink/50`).

**Semantic color rule (extends Phase 1):** `success`, `danger`, `warning` may now appear in:
- Toasts (left 4px colored bar + matching icon)
- Form input states (`danger` for invalid)
- Badges (`Excluído` warning, future stock-status badges)
- Buttons (`bg-danger hover:bg-red-700` for destructive only)
- Field-level error helper text (`text-danger text-xs`)

**Color contrast verification (WCAG):**
- `text-white` on `bg-brand-500` (#FFFFFF on #1863DC) = 5.4:1 — **AA pass** for normal text
- `text-white` on `bg-danger` (#FFFFFF on #CF2E2E) = 5.2:1 — **AA pass**
- `text-success` on `bg-white` (#009C34 on #FFFFFF) = 4.5:1 — **AA pass** at 14px
- `text-danger` on `bg-white` (#CF2E2E on #FFFFFF) = 5.2:1 — **AA pass**
- `text-warning` on `bg-warning/10` (#FCB900 on tinted yellow) — **uses icon + text together** per UX-13; warning never sole signal
- `text-brand-700` on `bg-brand-50` (#003F7D on #EFF4FC) = 11.8:1 — **AAA pass** (table header, pagination active)

**Focus management (UX-06, UX-13):**
- On open: focus moves to first focusable element in body (first input for Create, close button for Detail).
- Focus trap: Tab cycles inside the drawer; Shift+Tab cycles in reverse; focus never escapes.
- `Esc` closes the drawer.
- On close: focus returns to the element that opened it (CTA button or table row).
- Backdrop click closes only if no unsaved form changes (Create drawer guards via `isDirty`); Detail drawer (read-only) closes on backdrop click immediately.

## List 4-State Contract (UX-01)

`ProductsPage` (and every future paginated list) renders **exactly one** of these states at any moment. Toggle "Mostrar excluídos" is always visible at the top regardless of state.

### State 1 — Loading (initial fetch or pagination change)

```
Page title "Produtos" + "Cadastrar produto" primary button (top-right of page header, always visible)
+ Toggle "Mostrar excluídos" (above table)
+ <BaseTable> with 5 skeleton rows
+ Pagination disabled state (numbered buttons greyed)
```

Render trigger: `loading === true && items.length === 0` OR `loading === true && pagination change in flight`.

### State 2 — Empty (no products at all, no filter active)

```
Page title + "Cadastrar produto" primary button (top-right)
+ Toggle "Mostrar excluídos" (above area)
+ Centered empty state inside `min-h-[400px]`:
    [Inline SVG illustration ~120×120 — minimal line-art box with arrow, brand-500 stroke, no fill]
    <h2 class="text-lg font-semibold text-ink mt-6">Nenhum produto cadastrado</h2>
    <p class="text-sm text-muted mt-2 max-w-md text-center">Comece cadastrando o primeiro produto do seu catálogo. Você poderá registrar entradas e saídas de estoque em seguida.</p>
    <BaseButton variant="primary" class="mt-6">Cadastrar primeiro produto</BaseButton>
```

Render trigger: `loading === false && error === null && items.length === 0 && !showDeleted`.

**Filter-empty variant** (when `showDeleted === true` AND result is 0): same illustration, heading `Nenhum produto excluído`, body `Quando você excluir um produto, ele aparecerá aqui. Os produtos excluídos preservam o histórico de movimentações.`, **no CTA** (the toggle itself is the way to leave this state).

### State 3 — Error (fetch failed)

```
Page title + "Cadastrar produto" (top-right, still actionable)
+ Toggle (above area)
+ Centered error state inside `min-h-[400px]`:
    <AlertTriangle class="w-12 h-12 text-danger" />
    <h2 class="text-lg font-semibold text-ink mt-4">Não foi possível carregar os produtos</h2>
    <p class="text-sm text-muted mt-2 max-w-md text-center">{{ error.hint ?? error.message }}</p>
    <p class="text-xs text-muted mt-1">Código: {{ error.errorCode }} · ID: {{ error.traceId }}</p>
    <BaseButton variant="primary" class="mt-6" @click="retry()">Tentar novamente</BaseButton>
```

Render trigger: `loading === false && error !== null`. Network errors map to `apiError.hint: "Verifique sua conexão e tente novamente"` per `frontend/CLAUDE.md` client.ts shape.

`traceId` shown in small muted text — agentic differentiator (the evaluator can correlate to backend logs).

## Interaction Contracts

### Form field UX (UX-07, UX-12)

1. Label `block text-sm font-medium text-ink mb-1` above input (NEVER placeholder-as-label).
2. Required indicator: red asterisk after label text, `aria-hidden="true"`.
3. Input has `id`, label has matching `for`.
4. Error message `text-xs text-danger mt-1` immediately below input, with `id="{fieldId}-error"`.
5. Input has `aria-describedby="{fieldId}-error"` when an error is present (omit when no error).
6. Input has `aria-invalid="true"` when its error is present.
7. Focus ring `focus:ring-2 focus:ring-brand-500` (or `focus:ring-danger` for error state).
8. Helper text (when used, no Phase 2 surfaces use it): `text-xs text-muted mt-1`.
9. Submit button disabled while `!meta.valid || isSubmitting`.
10. On submit failure (validation): focus moves to the first invalid field via `nextTick(() => firstInvalidEl.focus())`.

### Modal / Drawer (UX-06, UX-13)

1. Open: focus moves to the documented first focusable element (Create drawer → first input; Detail drawer → close button; Delete modal → Cancel button).
2. Focus trap: Tab cycles internally.
3. `Esc` closes (with isDirty guard on Create drawer).
4. Backdrop click closes for read-only surfaces; for Create drawer, prompts native confirm if `isDirty`.
5. On close: focus returns to the trigger element via stored ref.
6. ARIA: `role="dialog" aria-modal="true" aria-labelledby="{drawerTitleId}"`.
7. Animation respects `prefers-reduced-motion: reduce`.
8. Body scroll is locked while drawer/modal is open (`overflow-hidden` on `<body>`).

### Toast (UX-03, UX-11)

1. Programmatic API: `useToast()` returns `{ success(msg), error(msg), info(msg), dismiss(id) }`.
2. Stack: newest pushes top of visual stack; max 3; oldest auto-evicts when overflow.
3. Auto-dismiss: success 3s, error 5s, info 3s. Pause on hover. Resume on hover leave.
4. Click dismisses immediately.
5. ARIA: success/info `role="status" aria-live="polite"`; error `role="alert" aria-live="assertive"`.
6. Animation: 200ms slide-in from right + opacity fade; respects reduced motion.
7. Error toast content is `apiError.hint ?? apiError.message` — **never** a hardcoded generic message except the documented `NETWORK_ERROR` fallback in `client.ts`.

### Table row interaction

1. Hover: row gets `bg-surface`.
2. Click anywhere in the row: opens Detail drawer.
3. Keyboard: row is `tabindex="0"`. `Enter` or `Space` triggers click.
4. Focus visible: `focus:ring-2 focus:ring-inset focus:ring-brand-500 bg-surface`.
5. Deleted rows: opacity-60, otherwise behave identically (still clickable, drawer opens with deletedAt visible).

### Pagination

1. URL is the source of truth — `/products?page=2&pageSize=30&includeDeleted=true` is bookmarkable.
2. Composable `usePagination` syncs to `useRoute` / `useRouter`.
3. Page change triggers `fetchPage(n)`; loading state activates; toggle remains visible.
4. After delete, if current page becomes empty (all items on this page were deleted), auto-navigate to `page = max(1, currentPage - 1)`.

### Toggle "Mostrar excluídos"

1. Default: OFF.
2. Toggling ON: refetches list with `?includeDeleted=true`, resets to page 1.
3. Toggling OFF: refetches without param, resets to page 1.
4. State persists in URL query string (`?includeDeleted=true`) so refresh preserves it.

## Accessibility Floor (Phase 2 — extends Phase 1)

In addition to Phase 1's a11y floor (semantic landmarks, wordmark H1, focus rings, color contrast, document.title), Phase 2 adds:

- **One H1 per `<main>` region** — `Produtos` is the H1 inside `<main>`; the sidebar wordmark `StockEasy` is the only H1 inside `<aside>`. Both are valid because they're in distinct landmark regions.
- **Drawer/Modal**: `role="dialog" aria-modal="true" aria-labelledby="{titleId}"`. Focus trap, focus return, `Esc` close — all enumerated above.
- **Tables**: `<table>` with `<thead>` + `<th scope="col">`. Each `<th>` has explicit `scope` attribute. Rows that are clickable are `tabindex="0"` with role-appropriate keyboard handlers.
- **Forms**: every input has an associated `<label for>`. Error messages connected via `aria-describedby`. `aria-invalid="true"` on invalid inputs. `aria-required="true"` on required inputs.
- **Toggle switch**: `<button role="switch" aria-checked="true|false" aria-label="Mostrar produtos excluídos">`.
- **Toasts**: `role="status"` / `role="alert"` with `aria-live` per variant. Dismiss button is real `<button aria-label="Dispensar">`.
- **Icons**: all `lucide-vue-next` icons receive `aria-hidden="true"` UNLESS they are the **sole** content of an interactive element (in which case the parent button gets `aria-label`).
- **Color contrast verified above (§Color)** — all combinations pass WCAG AA at minimum.
- **Keyboard-only navigation**: every interactive element reachable via Tab; visible focus indicator; no keyboard trap outside dialogs.
- **`prefers-reduced-motion`**: respected for drawer slide, modal scale, toast slide, skeleton pulse.
- **Color is never the sole signal**: error states combine icon + color + text; deleted rows combine opacity + badge + (drawer) red `deletedAt` value.

## Don'ts (Phase 2)

- ❌ Re-declaring Phase 1 tokens (palette, typography, spacing scale, sidebar contract) — inherit, don't redefine
- ❌ Introducing a UI component library (PrimeVue, Vuetify, Element Plus, shadcn-vue) — Base primitives are authored in-repo
- ❌ Inline `style="..."`, inline `<style scoped>` for non-animation CSS, or `:class` mixing PascalCase tokens
- ❌ Free-text `productType` rendering — always via `productTypeLabel`
- ❌ Inline `.toLocaleString()` / `.toFixed()` for currency/quantity/dates — always via `src/shared/format.ts`
- ❌ Hard-coded generic error toast messages — always `apiError.hint ?? apiError.message`
- ❌ Adding any additional font weight (e.g. `font-bold`, `font-normal`) to new surfaces
- ❌ Adding new color tokens outside the documented palette
- ❌ Editing product (no edit endpoint, no edit UI) — deferred to v2
- ❌ Hard-delete UI — soft delete only
- ❌ Confirmation modal on **create** — submit direct (CONF-03)
- ❌ Backdrop click closing Create drawer when `isDirty` without prompting
- ❌ Toast that doesn't auto-dismiss
- ❌ Submit button enabled when form is invalid
- ❌ Skeleton without `motion-reduce:animate-none`
- ❌ Drawer/modal without focus trap, focus return, or `Esc` handler
- ❌ Table row clickable via `<div onclick>` — must be semantic and keyboard-accessible (`tabindex="0"`, Enter handler)
- ❌ Icon-only buttons without `aria-label`
- ❌ Movement-specific surfaces — those belong to Phase 3
- ❌ Right-aligned `Cancelar` in modal/drawer footers — Cancel is **always on the left** of the primary action (UX-06)
- ❌ Page-level H1 duplication — exactly one H1 per landmark region
