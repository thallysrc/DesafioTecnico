ProductForm.vue:
- `defineEmits<{ (e:'submit', values: CreateProductForm): Promise<void>; (e:'dirtyChange', isDirty: boolean): void }>()`
- `defineExpose({ onSubmit, isSubmitting, isValid: () => meta.value.valid })`
- Internal Vee-Validate form with `validateOnBlur: true`
- Submits via `handleSubmit` which `emit('submit', formValues)` — re-throws on parent rejection

OutboundForm.vue:
- Internal Vee-Validate form
- Calls `productsApi.list(1, 100, false)` in `onMounted` to populate the searchable dropdown
- `selectedProduct` ref watches `values.productId`
- `preCheckError` computed: returns "Quantidade indisponível. Saldo: {formatQuantity(stock)}" when `values.quantity > selectedProduct.stockQuantity`
- `submitDisabled` computed: `!meta.valid || isSubmitting || preCheckError !== null`
- `onSubmit` handler: when `preCheckError === null` AND `selectedProduct` is set, sets `modalOpen.value = true` — does NOT call register
- `onConfirm` handler (modal's confirm): calls `useStockMovements.register({ productId, type: 'Outbound', quantity, saleValue })`. On INSUFFICIENT_BALANCE catches + toast + updates `selectedProduct.stockQuantity` from `apiError.details.available` (D-08).

useStockMovements.register: mocked at the api module seam (vi.mock '@/features/stock/api') so the composable's register is a thin wrapper over the mock.
