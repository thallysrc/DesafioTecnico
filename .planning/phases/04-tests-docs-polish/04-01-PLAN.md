<mockable_seams>
**StockMovementService transactional path uses `(NpgsqlConnection)_factory.Create()` then `await conn.OpenAsync()` then `await conn.BeginTransactionAsync()` — these are concrete Npgsql calls that Moq cannot intercept without a real connection.**

What IS mockable (and what we test):
1. **Idempotency fast-path replay** — `_movements.GetByIdempotencyKeyAsync(key)` returns non-null BEFORE the transactional block runs. Service short-circuits to `(MapToResponse(existing), IsReplay: true)`. Fully Moqable.
2. **GetByIdAsync (read path)** — pure repository call. Fully Moqable.
3. **ListAsync (read path)** — pure repository call. Fully Moqable.

What is NOT mockable with pure Moq (the transactional `CreateAsync` path that uses inline Dapper SQL on a real connection):
- The full Inbound / Outbound happy path
- INSUFFICIENT_BALANCE, PRODUCT_DELETED, PRODUCT_NOT_FOUND, INVALID_MOVEMENT_VALUES inside `CreateAsync`
- 23505 race-window recovery (catch + rollback + re-fetch)

**Resolution per CONTEXT.md D-02:** Cover those errorCodes by directly throwing/constructing the typed exceptions and asserting their public surface (ErrorCode, Message substring, non-null Hint, structured Details). The exception types are part of the domain contract — testing their constructors validates that the service WILL produce the right error envelope when it throws them.

Example (covers INSUFFICIENT_BALANCE without needing a real DB transaction):

```csharp
[Fact]
public void InsufficientBalanceException_Should_Carry_Trio_With_Dynamic_Hint()
{
    var productId = Guid.NewGuid();
    var ex = new InsufficientBalanceException(productId, "P3-SMOKE-001", requested: 10, available: 3);

    AssertDomain.Trio(ex, "INSUFFICIENT_BALANCE", "solicitado 10");
    Assert.Contains("disponível 3", ex.Message);
    Assert.NotNull(ex.Hint);
    Assert.Contains("máximo 3", ex.Hint);

    // Details shape (used by the frontend's local saldo refresh — D-08 in Phase 3)
    dynamic d = ex.Details!;
    Assert.Equal(productId, (Guid)d.productId);
    Assert.Equal("P3-SMOKE-001", (string)d.productCode);
    Assert.Equal(10, (int)d.requested);
    Assert.Equal(3, (int)d.available);
    Assert.Equal(7, (int)d.deficit);
}
```

This idiom satisfies TEST-02 + TEST-03 (covers every errorCode + asserts the trio) without needing to exercise the Npgsql connection. It's the same idiom the BancoShu test suite uses for its DomainException subclasses.

```csharp
public async Task CreateAsync_Should_Return_IsReplay_True_When_Idempotency_Key_Already_Exists()

    var key = Guid.NewGuid();

        Id = Guid.NewGuid(),
        ProductId = Guid.NewGuid(),
        ProductCode = "P001",

        Type = MovementType.Inbound,
        Quantity = 5,
        SupplierValue = 100m,
        SaleValue = null,
        IdempotencyKey = key,
        OccurredAt = DateTime.UtcNow,
        CreatedAt = DateTime.UtcNow,
    };
    _movements.Setup(m => m.GetByIdempotencyKeyAsync(key)).ReturnsAsync(existing);
    var sut = new StockMovementService(_factory.Object, _movements.Object);

    var request = new CreateMovementRequest(existing.ProductId, MovementType.Inbound, 5, 100m, null);
    var (response, isReplay) = await sut.CreateAsync(request, key);

    Assert.True(isReplay);
    Assert.Equal(existing.Id, response.Id);
    _movements.Verify(m => m.GetByIdempotencyKeyAsync(key), Times.Once);
    _movements.Verify(m => m.InsertAsync(It.IsAny<StockMovement>(), It.IsAny<IDbTransaction>()), Times.Never);
}
```
