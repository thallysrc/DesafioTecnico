    1. Create `docs/generate-pdfs.sh`:
       ```bash
       #!/usr/bin/env bash
       # Regenerates the three branded StockEasy PDFs in docs/dist/.
       #
       # Toolchain (host install — see docs/README.md):
       #   - pandoc            (apt: pandoc | brew: pandoc)
       #   - WeasyPrint        (apt: python3-weasyprint | pip: weasyprint | brew: weasyprint)
       #   - mermaid-filter    (npm: npm install -g mermaid-filter)
       #
       # Per CONTEXT.md D-17: regeneration is opt-in for the developer. The evaluator
       # never runs this script — they just open the committed PDFs in docs/dist/.

       set -euo pipefail

       SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
       cd "$SCRIPT_DIR"

       # Sanity-check the toolchain before doing anything destructive.
       for tool in pandoc weasyprint mermaid-filter; do
         if ! command -v "$tool" >/dev/null 2>&1; then
           echo "ERROR: '$tool' não encontrado no PATH." >&2
           echo "Instale conforme docs/README.md (pandoc + WeasyPrint + mermaid-filter)." >&2
           exit 1
         fi
       done

       mkdir -p dist

       DOCS=(
         "01-product-decisions"
         "02-architecture"
         "03-business-rules"
       )

       for doc in "${DOCS[@]}"; do
         echo "→ Gerando dist/${doc}.pdf"
         pandoc "${doc}.md" \
           --filter mermaid-filter \
           --template assets/pandoc-template.html \
           --css assets/pdf-style.css \
           --pdf-engine=weasyprint \
           --metadata=lang:pt-BR \
           -o "dist/${doc}.pdf"
       done

       echo "✓ PDFs regenerados em dist/:"
       ls -la dist/*.pdf
       ```

Plan 04-05 Task 1 just produced `docs/generate-pdfs.sh`. The script requires three host-level binaries: `pandoc`, `weasyprint`, `mermaid-filter`.

    **Claude CANNOT auto-install these** because:
    - `apt install` and `brew install` require either sudo or an existing brew/apt session — both are user-policy decisions per the project's "user decides when to install global tooling" stance
    - `npm install -g mermaid-filter` would write to the user's global npm prefix and (importantly) trigger Chromium download via puppeteer (mermaid-filter's dependency) — ~200 MB silent download
    - There is no idempotent, non-destructive way to verify the install succeeded without the user's involvement (e.g., browser sandbox flags vary by host)

    This is the ONE hard-human step in Phase 4 per the GSD playbook's `checkpoint:human-action` definition.
  </what-built>
  <how-to-verify>
    Run the install commands appropriate to your OS, then verify the three binaries are on the PATH:

    **Ubuntu/Debian:**
    ```bash
    sudo apt update
    sudo apt install -y pandoc python3-weasyprint
    npm install -g mermaid-filter
    ```

    **macOS:**
    ```bash
    brew install pandoc weasyprint
    npm install -g mermaid-filter
    ```

    **Arch / Manjaro / EndeavourOS:**
    ```bash
    sudo pacman -S pandoc python-weasyprint
    npm install -g mermaid-filter
    ```

    **Verify all three:**
    ```bash
    pandoc --version | head -1
    weasyprint --version
    mermaid-filter --version 2>/dev/null || command -v mermaid-filter
    ```

    All three commands MUST print something (binary name + version OR at least the path). If `mermaid-filter --version` doesn't exist as a flag, `command -v mermaid-filter` returning a path is sufficient.

    **Note on `mermaid-filter` first-run:** the first time mermaid-filter renders, it downloads Chromium via puppeteer (~150-200 MB). This happens silently inside `npm install -g mermaid-filter` on most setups; if not, the first invocation of `generate-pdfs.sh` will trigger it. Be patient on the first run.
  </how-to-verify>
