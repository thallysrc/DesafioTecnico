# Phase 3 — UI Design Contract

> Visual and interaction contract for **Stock Movements (Inbound / Outbound / Histórico)**.
> Scope: `StockMovementsPage` tab strip + `InboundForm` + `OutboundForm` + `ConfirmOutboundModal` (CONF-01) + `MovementHistory` (4-state table with filters) + `movementTypeLabel` addition.
> Generated by gsd-ui-researcher (auto mode), verified by gsd-ui-checker.

**Extends Phase 2 UI-SPEC** — palette, typography, spacing, all 15 `Base*` primitives, composables (`useToast`/`useConfirm`/`usePagination`), `format.ts`, the 4-state list contract, drawer/modal/toast tokens, form-field UX, and accessibility floor are **already locked** there and inherited as-is. This document only declares the **net-new** patterns and copy that Phase 3 introduces — primarily the tab strip composition, the "Disponível: N unidades" helper text, the CONF-01 modal copy, and the Entrada/Saída badge color mapping.

**Out of scope for this UI-SPEC** (Phase 4 territory):
- xUnit/Vitest test fixtures
- PDF doc generation
- README polish

**Out of scope by product decision** (deferred — do NOT design):
- Edit / delete movement (immutable history)
- Bulk movements / CSV upload
- "Saldo após" historical column (derivable, not persisted in v1)
- Idempotency-Replay UX disclosure (silent — no "you already submitted" banner)
- Multi-warehouse transfers / kardex / low-stock alerts

- `text-danger` on `bg-danger/10` = ~4.7:1 → **AA pass**, same reasoning
- `text-muted` on `bg-white` (tab inactive, helper text) = 4.7:1 → **AA pass** (inherited from Phase 1)
- `text-white` on `bg-brand-500` (CONF-01 confirm button) = 5.4:1 → **AA pass** (inherited)

## Tab Strip Composition (NEW pattern, no primitive)

Inline composition in `StockMovementsPage.vue`. **No `BaseTabs` component is authored.** The tab strip is three `<button>` elements wrapped in a `<nav role="tablist">` container.

### Structure (locked)

```html
<nav role="tablist" aria-label="Seções de movimentação" class="flex items-center gap-1 border-b border-line mb-6 h-12">
  <button
    role="tab"
    type="button"
    :aria-selected="activeTab === 'entrada'"
    :tabindex="activeTab === 'entrada' ? 0 : -1"
    @click="setTab('entrada')"
    @keydown="onTabKeydown"
    :class="tabClasses('entrada')"
  >
    Entrada
  </button>
  <button role="tab" type="button" ... >Saída</button>
  <button role="tab" type="button" ... >Histórico</button>
</nav>

<section role="tabpanel" :aria-labelledby="..." tabindex="0">
  <!-- active tab content (InboundForm / OutboundForm / MovementHistory) -->
</section>
```

### Tab button states (locked Tailwind)

| State | Tailwind classes |
|-------|------------------|
| Base (always applied) | `inline-flex items-center justify-center px-4 h-12 -mb-px text-sm font-medium transition-colors focus:outline-none focus:ring-2 focus:ring-brand-500 focus:ring-offset-2 rounded-t-md` |
| Inactive | `... text-muted hover:bg-surface hover:text-ink border-b-2 border-transparent` |
| Active | `... text-brand-700 border-b-2 border-brand-500 bg-white` |
| Disabled (reserved — not used in v1) | `... text-muted opacity-50 cursor-not-allowed` |

**Active-indicator detail:** the `-mb-px` offset on the tab button ensures the active tab's `border-b-2 border-brand-500` visually replaces the strip's underline at exactly the active tab's width (1px overlap with `border-b border-line` on the `<nav>`).

### Keyboard contract (WAI-ARIA tabs pattern)

| Key | Behavior |
|-----|----------|
| `Tab` (from outside) | Focuses the **active** tab (only the active tab is in tab order; inactive tabs have `tabindex="-1"`) |
| `ArrowRight` / `ArrowDown` | Move focus to next tab (wraps from last → first) |
| `ArrowLeft` / `ArrowUp` | Move focus to previous tab (wraps from first → last) |
| `Home` | Focus first tab |
| `End` | Focus last tab |
| `Enter` / `Space` | Activate the focused tab (same as click) |

**Activation model:** **automatic** — focus change activates the tab and swaps content (`activeTab` follows focus). This matches the simpler ARIA "tabs with automatic activation" pattern. Acceptable here because tab content is cheap to render (forms / paginated list); not appropriate for tabs whose content makes network calls on activation — history `fetchPage` already happens automatically and is the lightest of the three.

### URL sync (deep-linkable)

- URL query param `?tab=entrada|saida|historico` is the source of truth.
- Default when param absent: `historico` (per CONTEXT.md D-01).
- Composable inside `StockMovementsPage` watches `useRoute().query.tab`; setting a tab calls `router.replace({ query: { ...current, tab } })`.
- History filters (`productId`, `startDate`, `endDate`, `page`) are preserved across tab swaps (URL keeps them).

### Forbidden

- ❌ Using `<a>` / `<RouterLink>` for tabs (these would change route, not query param)
- ❌ Hiding inactive tab content with `v-show` while preserving its DOM — use `v-if` so closed tabs don't run validators or fetch
- ❌ Sticky-positioning the tab strip until a real scroll problem emerges (deferred — CONTEXT.md notes "Sticky tab bar" as nice-to-have, but the page rarely exceeds viewport with default pageSize)
- ❌ Adding a 4th tab in v1 (out of scope)

## "Disponível: N unidades" Helper Text Contract (NEW, UX-08)

Shown **above the quantity input** in `OutboundForm.vue` once a product is selected. Updates on product change. Refreshes on successful Outbound submit (per CONTEXT.md D-03, re-fetches product via `productsApi.getById(productId)`).

### Visual contract

```html
<!-- Label row (above the input) -->
<div class="flex items-center justify-between mb-1">
  <label for="qty" class="block text-sm font-medium text-ink">
    Quantidade <span class="text-danger" aria-hidden="true">*</span>
  </label>
  <span class="text-xs text-muted" aria-live="polite" :aria-atomic="true">
    Disponível: <span class="font-medium text-ink">{{ formatQuantity(stockQuantity) }}</span> unidades
  </span>
</div>

<BaseInput id="qty" type="number" min="1" step="1" inputmode="numeric" ... />
```

### Variants

| Trigger | Render |
|---------|--------|
| No product selected | helper hidden (`v-if="selectedProduct"`) |
| Product selected, `stockQuantity > 0` | `Disponível: {formatted} unidades` in `text-xs text-muted` with the number in `font-medium text-ink` |
| Product selected, `stockQuantity === 0` | `Disponível: 0 unidades` rendered in `text-xs text-danger font-medium` + AlertTriangle icon (`<AlertTriangle class="w-3 h-3 inline -mt-0.5" />`); submit button stays disabled because Zod schema's `min(1)` plus the local pre-check (CONTEXT.md D-08) keeps the form invalid |
| `quantity > stockQuantity` (pre-check fail) | input gets `border-danger` (inherited error state), helper line below input reads `Quantidade indisponível. Saldo: {n}` in `text-xs text-danger`; submit disabled |

**ARIA:** the `<span>` carrying the disponível count uses `aria-live="polite"` so screen readers announce the new value when a product is picked or after submit refresh. `aria-atomic="true"` ensures the whole phrase is announced, not just the changed digits.

**Format:** `formatQuantity(stockQuantity)` from Phase 2's `src/shared/format.ts` — no inline `.toLocaleString()`.

**Forbidden:**
- ❌ Rendering "Disponível: undefined unidades" — guard with `v-if="selectedProduct"`
- ❌ Showing the helper without a selected product (avoid empty `Disponível: —`)
- ❌ Using `text-success` for positive balance — green is reserved for Entrada badge / toast success; the disponível counter is informational, not celebratory

Reuses Phase 2's `BaseModal` centered variant (max-w-md, fade-in, focus management, Esc-close, backdrop-close). The only net-new content is the locked copy below.

### Structure (locked)

```html
<BaseModal :open="open" @close="onCancel" aria-labelledby="conf-out-title">
```

### Locked copy (PT-BR, verbatim — auditor will grep)

| Element | Copy |
|---------|------|
| Title (`<h2 id="conf-out-title">`) | `Confirmar saída?` |
| Lead paragraph | `Esta operação registra uma saída de estoque. Confira o resumo abaixo antes de confirmar.` |
| Definition term — produto | `Produto:` |
| Definition term — quantidade | `Quantidade:` |
| Definition term — valor de venda | `Valor de venda:` |
| Definition term — saldo atual | `Saldo atual:` |
| Definition term — saldo resultante | `Saldo resultante:` |
| Unit suffix on quantities | ` unidades` (note leading space; rendered after the formatted number) |
| Cancel button | `Cancelar` |
| Confirm button | `Confirmar saída` |
| In-flight confirm button | `Registrando saída...` (replaces `Confirmar saída` while `isSubmitting === true`, with `<Loader2 class="w-4 h-4 animate-spin" />` icon) |

### Behavior contract

1. **Open trigger:** `OutboundForm.vue` `handleSubmit` — only opens after Zod validation passes AND local balance pre-check passes (`quantity <= currentStock`).
2. **Focus on open:** `data-autofocus` on the **Cancelar** button (safer default per Phase 2 modal pattern — Enter cannot trigger confirm by accident).
3. **Esc:** closes the modal (calls `onCancel`); form data is preserved (Nielsen #3 — CONTEXT.md D-02).
4. **Backdrop click:** closes the modal (read-equivalent surface — confirm modal has no in-modal data entry beyond two buttons; backdrop close is safe).
5. **Cancel:** closes the modal; the Outbound form stays filled; no API call.
6. **Confirm:** disables both buttons, swaps Confirm label to `Registrando saída...` with spinner, calls `useStockMovements.create({ productId, type: 'Outbound', quantity, saleValue })` (Idempotency-Key generated inside the composable per FRONT-12).
7. **Confirm success:**
   - Modal closes
   - Toast `Saída registrada com sucesso` (success variant, 3s) — see Copywriting Contract
   - Outbound form clears (all fields reset)
   - Disponível helper refreshes via `productsApi.getById(productId)` (CONTEXT.md D-03)
8. **Confirm error:**
   - Modal stays open (allows quick retry or cancel)
   - Toast (error variant, 5s) consumes `apiError.hint ?? apiError.message`
   - Special case: `errorCode === 'INSUFFICIENT_BALANCE'` → toast hint already reads `Reduza a quantidade para no máximo {N} ou registre uma entrada antes.` (constructed in backend per AGENT-08). The form's `currentStock` ref is updated from `apiError.details.available` so the local Disponível helper refreshes immediately and a follow-up submit pre-checks against the real value.
   - Special case: `errorCode === 'PRODUCT_DELETED'` → toast hint reads the backend's dynamic hint; modal closes (no useful retry) and the form's product field clears (the product is no longer valid).
   - Special case: `errorCode === 'MISSING_IDEMPOTENCY_KEY'` → toast `Erro inesperado ao registrar saída. Tente novamente.` This path is a frontend bug (the composable should always inject the header); shouldn't be reachable but is handled for completeness.

### Forbidden

- ❌ Title `Confirmar saída de estoque?` or `Confirma saída?` — exact string is `Confirmar saída?`
- ❌ Destructive (`bg-danger`) styling on the Confirm button — Outbound is a normal business operation
- ❌ Auto-focus on the Confirm button (Cancel keeps the safe default)
- ❌ Backdrop click silently ignored — it closes
- ❌ Computing "Saldo resultante" in-template via inline arithmetic without `tabular-nums` — always tabular-nums on number columns
- ❌ Omitting any of the 5 definition rows — the full resumo is the entire value of CONF-01
- ❌ Inline `R$` prefix or `.toFixed(2)` — always `formatCurrency`

## Surfaces (page-by-page contract)

### `StockMovementsPage` (`/stock-movements`)

**Layout** (top to bottom inside `<main class="flex-1 p-6 overflow-auto">`):

1. Header row: `<h1>Movimentação de Estoque</h1>` (left) — **no primary CTA in the page header** (the "primary action" surface for each capability lives inside its respective tab content).
2. Tab strip (see §"Tab Strip Composition") — `<nav role="tablist">` with three tabs.
3. Tab content region: `<section role="tabpanel">` switching between `<InboundForm />`, `<OutboundForm />`, `<MovementHistory />` via `v-if` (mount/unmount on tab change).

**Wrapping container:** `<div class="max-w-7xl mx-auto">`.

**Default tab:** `historico` (per CONTEXT.md D-01). On first visit (no `?tab=` param), URL is replaced with `?tab=historico`.

**Page-level title rule (a11y):** `Movimentação de Estoque` is the **only H1 inside `<main>`** — same constraint enforced in Phase 2's `ProductsPage`. Tab labels are buttons (not headings), and form/modal titles are H2.

### `InboundForm` (under Entrada tab)

**Header:** none — the tab label is the section header. (The form is visually direct content of the tabpanel.)

**Body — form fields in this exact vertical order:**

1. `Produto` (`BaseSearchableSelect`) — required. Options sourced from `productsApi.list(1, 100, includeDeleted=false)` on mount. Display format `{code} — {description}`. Search filters both code and description case-insensitively. Empty state inside the dropdown (no results) shows `Nenhum produto encontrado` in `text-xs text-muted`.
2. `Quantidade` (`BaseInput type="number" min="1" step="1" inputmode="numeric"`) — required. **No "Disponível" helper** here (Entrada has no balance constraint; Disponível is Outbound-only per UX-08).
3. `Valor do fornecedor` (`BaseInput mask="currency-brl"`) — required. Same comma-decimal currency mask as Phase 2's ProductForm (parses `1.234,56` → `1234.56` JS number).

Vertical rhythm `gap-4` (16px) between fields. Form max width `max-w-2xl`.

**Validation behavior (mirrors Phase 2 ProductForm):**
- `validateOnBlur: true`, `validateOnInput: false`, `validateOnChange: false`
- Submit button disabled while `!meta.valid || isSubmitting`
- `aria-invalid` and `aria-describedby` on error per Phase 2 form contract

**Footer (right-aligned, gap-3):**
- Right: `Registrar entrada` (primary) — primary button, no left-side `Cancelar` because there's nothing to cancel back to (the form is the tab content, not a drawer). If the user wants to abandon, they tab away.

**Submit success path:**
1. POST `/api/stock-movements` returns 201 (Idempotency-Key injected by `movementsApi.register`)
2. Toast `Entrada registrada com sucesso` (success, 3s)
3. Form clears (all fields reset, product searchable select reverts to placeholder)
4. **No tab change** — user stays on Entrada to register another

**Submit error path:**
1. Toast (error, 5s) with `apiError.hint ?? apiError.message`
2. Form stays filled
3. If `errorCode === 'VALIDATION_ERROR'` and `details.fields[]` present → field-level errors applied (Phase 2 pattern)
4. `PRODUCT_DELETED` → toast hint surfaces; product select clears (the deleted product is no longer a valid choice)

## Interaction Contracts (Phase 3 — additions)

### Tab strip (NEW)

Full keyboard contract documented under §"Tab Strip Composition". Recap:

1. URL query `?tab=...` is the source of truth.
2. Default tab when param absent: `historico`.
3. Inactive tabs: `tabindex="-1"`. Active tab: `tabindex="0"`.
4. Arrow keys cycle focus (with wrap). Focus = activation.
5. Tab content uses `v-if` (not `v-show`) so closed tabs don't run schemas or fetch.
6. Filters in History tab persist across tab swaps (URL keeps them).

### Disponível helper text (NEW, UX-08)

1. Hidden until product is selected.
2. Updates on product change (synchronous — uses selected product's cached `stockQuantity`).
3. Refreshes after successful Outbound submit via `productsApi.getById(productId)`.
4. `aria-live="polite"` + `aria-atomic="true"` so SR announces the new value.
5. Visual color: `text-muted` for positive balance; `text-danger` with icon when balance is 0 (still rendered, communicates "this product is empty").

### CONF-01 confirmation (extends Phase 2 modal pattern)

1. Open from `Registrar saída` only after Zod + local pre-check pass.
2. `data-autofocus` on Cancel.
3. Esc / backdrop click / Cancel button all dismiss without API call; form state preserved.
4. Confirm POSTs (with Idempotency-Key from composable).
5. Success: modal closes → success toast → form clears → product re-fetched for fresh disponível.
6. Error: modal stays open; toast surfaces; INSUFFICIENT_BALANCE updates local `currentStock` from `details.available`.

### History filters (NEW)

1. URL query is source of truth (`productId`, `startDate`, `endDate`, `page`, `tab=historico`).
2. Product select debounced 300ms; dates immediate.
3. Filter change → refetch with new params; reset to page 1.
4. `Limpar filtros` resets all three filters + page; URL becomes `?tab=historico`.
5. Empty date range with one end set: focusing the other date input defaults it to today (only on first focus, doesn't override user input on subsequent focuses).

### Movement-type badge (NEW activation)

1. Badge in Tipo column shows label + icon; icon is `aria-hidden="true"`.
2. Color mapping is fixed: Entrada=success, Saída=danger.
3. Badge text comes from `movementTypeLabel[movement.type]`, never inline.

## Accessibility Floor (Phase 3 — extends Phase 1/2)

In addition to Phase 1/2's accessibility floor:

- **Tab strip ARIA**: `<nav role="tablist" aria-label="Seções de movimentação">` wraps three `<button role="tab" aria-selected aria-controls>` elements; the active panel uses `role="tabpanel" aria-labelledby` referencing the active tab's id. Keyboard contract per WAI-ARIA tabs pattern (see §"Tab Strip Composition").
- **One H1 per `<main>` region**: `Movimentação de Estoque` is the only H1 inside `<main>` (the sidebar wordmark `StockEasy` is the only H1 inside `<aside>`).
- **Form labels**: every input has `<label for>`. The Disponível helper carries `aria-live="polite" aria-atomic="true"` for dynamic balance announcements.
- **Modal (CONF-01)**: inherits Phase 2 modal a11y (`role="dialog" aria-modal="true" aria-labelledby`, focus trap, focus return, Esc close).
- **Badges**: text label is the accessible name; icon is `aria-hidden="true"`; color is reinforced by text, never sole signal.

- **Filter inputs**: date inputs use native `<input type="date">` (browser-provided a11y); product searchable select inherits BaseSearchableSelect's keyboard contract (Phase 2: typeahead, ArrowUp/ArrowDown navigation, Enter select, Esc close).
- **`prefers-reduced-motion`**: respected for modal scale + skeleton pulse (inherited).
- **Color contrast**: all new combinations verified above pass WCAG AA.

## Don'ts (Phase 3)

- ❌ Authoring a `BaseTabs` primitive — tabs compose inline in `StockMovementsPage.vue`
- ❌ Using `<RouterLink>` or `<a>` for tabs — they're `<button role="tab">` elements that mutate `?tab=` via `router.replace`
- ❌ Using `v-show` to keep all three tab subtrees mounted — `v-if` only (forms shouldn't validate while hidden, history shouldn't fetch while hidden)
- ❌ Sticky tab bar in v1 (deferred — re-evaluate if user feedback says scroll-out is a problem)
- ❌ Destructive (`bg-danger`) styling on the `Confirmar saída` button — Outbound is a normal business op (CONTEXT.md D-02)
- ❌ Auto-focus on the Confirm button in CONF-01 — Cancel keeps the safe default per Phase 2 modal pattern
- ❌ Free-text `'Inbound' ? 'Entrada' : 'Saída'` — always via `movementTypeLabel`
- ❌ Inline `.toLocaleString()`, `.toFixed()`, or `R$ ` prefixes — always via `formatCurrency` / `formatDate` / `formatQuantity`
- ❌ Hardcoded generic error toast messages — always `apiError.hint ?? apiError.message`
- ❌ Submit-button enabled while form is invalid OR while quantity > disponível (Outbound)
- ❌ Submitting Outbound without the CONF-01 modal — never bypass confirmation (CONF-01 is the locked contract)
- ❌ Submitting any movement without `Idempotency-Key` — `movementsApi.register` injects it automatically; do not call POST directly from a component
- ❌ Re-submitting an in-flight movement (button must `disabled` while `isSubmitting`)
- ❌ Showing "Disponível" helper on Inbound (it's Outbound-only — UX-08)
- ❌ Rendering "Saldo resultante" without `tabular-nums` (numbers shift width across digits)
- ❌ Adding any new font weight or color token beyond what Phase 1/2 declared
- ❌ Inverting Entrada/Saída color mapping (Entrada=green, Saída=red — locked)
- ❌ Editing or deleting a movement from the UI (immutability — MOVE-11)
- ❌ Showing a "Saldo após" column in history (deferred — not persisted in v1)
- ❌ Surfacing "Idempotency-Replay" to the user — silent success only (CONTEXT.md D-07)
- ❌ A movement detail drawer in v1 (deferred; rows are non-interactive)
- ❌ Bulk movement / CSV upload UI
